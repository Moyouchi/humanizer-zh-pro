## 为什么用这个？

你让 AI 写了一篇文章，读起来「哪儿都对，但就是不对劲」——句式模板化、满篇「赋能」「闭环」「底层逻辑」、每个段落都像同一个人用同一种语气在念稿。

| 你遇到的问题 | humanizer-zh-pro 怎么做 |
|-------------|----------------------|
| 满篇「首先/其次/最后/综上所述」模板腔 | 6 大类 AI 味诊断（内容/句式壳/结构/词汇/标点/工具指纹），逐句定位 |
| 改完之后意思变了、数据丢了 | **保真契约** 5 条：数字绑定、专有名词零篡改、引号锁定、关系不漂移、不编造 |
| 改完还是像 AI 写的 | **二次审计**：改后重跑诊断评分，降幅不足 30% 则回退重改 |
| 不同场景（公众号/小红书/知乎）改法一样 | **7 场景差异化**：blog/social/zhihu/casual/business/academic/fiction，词汇豁免 + 句式节奏各自不同 |
| 句子长度全一样，读起来没有呼吸感 | **MLS 句式功能系统**：每句判定功能（核句/卫句/衔接句/短促句），强制功能错序 + 句长波动 |
| 不知道改完到底自然不自然 | **真人感指数**：4 项量化指标（细节密度/第一人称占比/句长方差/口语化标记） |

## 演示

**改写前**（AI 热词堆砌）：

> 「通过底层逻辑的拆解，可以发现这套系统实现了全链路的数字化赋能，形成了数据驱动的闭环生态，重构了行业的底层范式。」

**改写后**：

> 「拆开看，这套系统做的事其实很简单：从头到尾把数据打通了。以前每个环节各管各的，现在数据跑了一圈能接上——这圈跑通了，整个行业做事的方式就变了。」

**改写逻辑**：底层逻辑→拆开看 / 全链路→从头到尾 / 赋能→把数据打通 / 闭环→跑了一圈能接上 / 生态→删 / 底层范式→做事的方式

## 和其他工具有什么不同？

| 维度 | 常见做法 | humanizer-zh-pro |
|------|---------|-----------------|
| 诊断方式 | 笼统判断「有没有 AI 味」 | **6 大类 × 百字归一化评分**（0-100 量化） |
| 改写方法 | 关键词替换（「赋能」→「帮」） | **MLS 句式功能驱动**：按修辞功能分配句长，强制节奏波动 |
| 保真能力 | 缺少系统的保真检查 | **保真契约 5 条** + 逐段自检，任一违反则该段回退 |
| 质量控制 | 改完即结束 | **二次审计**：重跑诊断 → 评分降幅不足 30% 回退 |
| 场景适配 | 一个模版改所有 | **7 场景差异化**：公众号/小红书/知乎/口语/商务/学术/小说 |
| 热词处理 | 统一删除 | **场景豁免表**：18 词 × 7 场景逐词判断。学术论文中的「范式」是 Kuhn 标准术语、商务场景的「闭环」是行业用语——不会被误杀 |
| 量化效果 | 靠感觉判断 | **真人感指数**：细节密度/第一人称占比/句长方差/口语化标记，可对比改写前后 |

## 功能详解

### 1. 6 大类 AI 味诊断与评分（0-100）

| 类别 | 权重 | 检测内容 |
|------|:--:|---------|
| 内容类 | 15% | 夸大意义、模糊归属、立场真空、幻影引用 |
| 句式壳 | 20% | 二元对立、分步序列、本质论断、金句公式 |
| 结构类 | 10% | 三段论模板、平行结构泛滥、列表膨胀 |
| 词汇类 | 20% | AI 热词、空洞修饰、翻译腔、同义词循环 |
| 标点版面 | 10% | 破折号过密、粗体轰炸、逗号-解释链 |
| 工具指纹 | 5% | `[cite: N]`、`utm_source=chatgpt.com` 等截断痕迹 |

### 2. MLS 句式功能驱动改写

每句话先判定修辞功能，再分配目标长度，强制段落节奏波动：

| 句式功能 | 目标长度 | 用途 |
|---------|:---:|------|
| **核句** | ≤20 字 | 断言收束（核心论点、结论） |
| **卫句** | 20-45 字 | 论证展开（证据链、复杂陈述） |
| **衔接句** | ≤15 字 | 逻辑连接（过渡、转向） |
| **短促句** | ≤8 字 | 强调/停顿（数字锚点、反问、碎句） |

规则：同一段内不连续两句用同一功能、全文最短句与最长句字数比 ≥1:2.5。

### 3. 保真契约（5 条铁律）

改写前锁定不可改内容。任一条违反 → 该段回退重改：

1. 数字+修饰对象绑定（「增长 30%」的 30% 必须跟着「增长」走）
2. 专有名词零篡改（人名、地名、机构名、产品名原样）
3. 引号边界锁定（引文、法条原文、当事人原话不动）
4. 关系不漂移（因果、转折、递进逻辑不反转）
5. 缺信息不编造、原文实质信息不删除

### 4. 7 场景差异化

| 场景 | 核句密度 | 词汇处理 | 特殊规则 |
|------|:--:|---------|---------|
| blog（公众号） | 中 | 热词全清，空洞修饰硬删 | 卫句可突破 45 字 |
| social（小红书/微博） | 高 | 热词全清，保留平台特有语感词 | 核句可短至 8 字 |
| zhihu（知乎） | 中 | 保留行业术语，仅清空泛热词 | 核句观点前置 |
| casual（口语/朋友圈） | 极高 | 热词全清，大白话替代 | 核句 5-8 字，允许不完整句 |
| business（商务） | 低 | 仅清空泛热词，保留行业术语 | 保持正式语体 |
| academic（学术） | 低-中 | 仅清空泛热词和空洞修饰 | 保留学术严谨性 |
| fiction（小说） | 灵活 | 清 AI 热词但保留叙事必需词汇 | 紧张处核句连击 |

### 5. 二次审计

改写完成后自动执行：

- **AI 味残留检测**：重跑诊断评分，降幅不足 30% 则回退
- **保真校验**：逐条核对保真契约 5 条
- **MLS 合规**：逐段校核节奏规则
- **Hedging 密度**：每 200 字模糊限定词 ≤2 个
- **标点审计**：破折号/冒号/分号每千字密度统计，超标的用逗号/句号替代

## 安装与使用

```bash
# 一行命令克隆
git clone https://github.com/Moyouchi/humanizer-zh-pro
```

将 `SKILL.md` 加载到你的 AI 工具即可使用。

### 工作模式

| 模式 | 说明 |
|------|------|
| **annotate** | 先输出诊断报告（含 AI 味评分 + 命中明细），等确认后改写 |
| **rewrite** | 直接改写 + 简版报告 |
| **quick** | 短文完整流程：轻量诊断 + 简化 MLS 节奏（核句锚点 + 句长比校验）+ 热词处理 + 快速审计，适合 <500 字短文；<200 字自动走极速档 |
| **auto**（默认） | <500 字自动直改，≥500 字先诊断等确认 |

### OpenCode / Trae

```bash
# 克隆到本地
git clone https://github.com/Moyouchi/humanizer-zh-pro ~/.opencode/skills/humanizer-zh-pro
```

### 虾评（Coze 技能评测平台）

搜索「humanizer-zh-pro」一键安装，或访问 [虾评页面](https://xiaping.coze.com/skill/62732ce1-05e3-4f9f-bc31-a05dc1624d82)。

### Claude Code / Codex

将 `SKILL.md` 作为自定义 skill 文件加载，或复制到对应工具的 skills 目录。

### 触发方式

在任何支持的 AI 工具中，发送以下自然语言即可自动触发：

- 「帮我去 AI 味」
- 「这段读起来太像 AI 写的了」
- 「改得像人写的」
- 「润色成中文母语表达」
- 「降 AIGC 率」
